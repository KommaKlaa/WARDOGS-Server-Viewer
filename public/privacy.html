2. Hosting / Bereitstellung der Website

Beim lokalen Betrieb auf dem eigenen PC werden keine öffentlichen Website-Logs durch dieses Projekt bereitgestellt. Nutzt jemand die App hinter einem eigenen Webserver, gelten die Log-Regeln dieses eigenen Hostings.

3. Server-Logdaten der Node-Anwendung

Die Node-/Express-Anwendung selbst schreibt keine umfassenden Request-Zugriffsprotokolle. In der Produktionskonfiguration werden Fehler in der Regel nur mit Fehlercode/Status geloggt, ohne Stack-Traces an den Browser auszugeben. Optionales serverseitiges Debug-Logging (WARDOGS_DEBUG=1) ist nur aktiv, wenn ausdrücklich als Umgebungsvariable konfiguriert; es gibt keinen öffentlichen Browser-Debug-Schalter.

Für den vorgesehenen lokalen Desktop-Betrieb gibt es keine zentrale Hosting-Log-Aufbewahrung durch den Projektbetreiber.

4. Sicherheit / Rate Limiting

Zum Schutz vor Missbrauch nutzt die Anwendung express-rate-limit für die Route /api/*.

  • Identifikator: Client-IP (request.ip, mit IPv6-Normalisierung)
  • Fenster: 60 Sekunden
  • Limit: 240 Anfragen pro Fenster
  • Speicher: Standard-MemoryStore (nur Arbeitsspeicher, kein Disk-/DB-Persistenz durch die App)

Mögliche Rechtsgrundlage (Vorlage zur Prüfung): Art. 6 Abs. 1 lit. f DSGVO (berechtigte Interessen an sicherem Betrieb, Missbrauchsprävention, Verfügbarkeit und Fehleranalyse).

5. Local Storage / Einstellungen

Die Anwendung setzt keine eigenen Cookies und verwendet kein sessionStorage. Permanente Komforteinstellungen werden nur gespeichert, wenn der Nutzer ausdrücklich aktiviert: „Einstellungen auf diesem Gerät speichern“ / „Remember settings on this device“ (Standard: aus).

Nach ausdrücklicher Aktivierung können folgende localStorage-Schlüssel gesetzt werden:

  • wardogs-storage-consent — speichert nur, dass die Persistenz ausdrücklich gewünscht wurde (granted-v1)
  • wardogs-language — gewählte UI-Sprache (DE/EN)
  • wardogs-viewer-settings-v1 — JSON mit Filtern/Einstellungen (u. a. Mein Level, Regionen, Karte, Level-Filter, Level-Cap, Sortierung, Belegung)

Gespeicherte Präferenzen verbleiben im Browser des Nutzers. Dritte erhalten diese Werte nicht über Tracking-Mechanismen dieser Anwendung. Wird die Speichern-Option wieder deaktiviert, werden die genannten Anwendungsschlüssel sofort entfernt. Aktive Filtereinstellungen bleiben bis zum nächsten Neuladen in der laufenden Sitzung nutzbar.

Ohne Aktivierung funktioniert die Anwendung vollständig mit Session-/Runtime-Zustand; nach einem Neuladen gelten wieder Standardwerte bzw. die Browser-Sprache. Es wird kein Cookie-Banner ausgeliefert (keine Anwendungs-Cookies, kein Tracking).

6. WARDOGS-Serverdaten / Backend-API

Der Browser kommuniziert ausschließlich mit unserem Backend unter /api/.... Das Backend ruft serverseitig die Wardog-Servers-API unter https://api.wardogservers.com auf. Es findet kein direkter Browser-Aufruf dieser Upstream-API statt.

Dabei werden Live-Serverlisten, Regionsdaten, Server-Details und Map-History abgefragt, um die Viewer-Funktion bereitzustellen. Antworten können serverseitig zwischengespeichert werden.

8. Keine Analyse / Werbung / Profiling

Die Anwendung enthält keine Analyse-/Tracking-Skripte, kein Advertising, keine Social-Media-Pixel und keine Third-Party-Fonts. Frontend-Assets (CSS/JS/Bilder/Logos) werden lokal ausgeliefert.

9. Speicherdauer

  • Rate-Limit-Zähler: flüchtig im Arbeitsspeicher, Fensterbezogen

2. Hosting / website delivery

In the intended local desktop use, this project does not provide public website access logs. If someone runs the app behind their own web server, that host’s logging rules apply.

3. Node application logging

The Node/Express application itself does not write comprehensive request access logs. In production, errors are typically logged as code/status only, without exposing stack traces to the browser. Optional server-side debug logging (WARDOGS_DEBUG=1) is only active when explicitly configured as an environment variable; there is no public browser debug toggle.

For the intended local desktop use there is no central hosting-log retention by the project operator.

4. Security / rate limiting

To reduce abuse, the application uses express-rate-limit on /api/*.

  • Identifier: client IP (request.ip, with IPv6 normalization)
  • Window: 60 seconds
  • Limit: 240 requests per window
  • Store: default MemoryStore (in-memory only; not persisted to disk/DB by the app)

Possible legal basis (template for review): Art. 6(1)(f) GDPR (legitimate interests in secure operation, abuse prevention, availability and troubleshooting).

5. Local storage / preferences

The application does not set its own cookies and does not use sessionStorage. Permanent convenience preferences are stored only when the user explicitly enables “Remember settings on this device” / “Einstellungen auf diesem Gerät speichern” (default: off).

After explicit activation, the following localStorage keys may be set:

  • wardogs-storage-consent — records only that persistence was explicitly requested (granted-v1)
  • wardogs-language — selected UI language (DE/EN)
  • wardogs-viewer-settings-v1 — JSON with filters/settings (including My Level, regions, map, level filter, level cap, sort, occupancy)

Saved preferences remain in the user’s browser. Third parties do not receive those values through tracking mechanisms of this application. Disabling the preference immediately removes the listed application keys. Active filter settings remain usable in the current session until reload.

Without activation the application works fully with session/runtime state; after reload, defaults / browser language apply again. No cookie banner is shipped (no application cookies, no tracking).

6. WARDOGS server data / backend API

The browser communicates only with our backend at /api/.... The backend calls the Wardog Servers API at https://api.wardogservers.com server-side. There is no direct browser call to that upstream API.

Live server lists, region data, server details and map history are retrieved to provide the viewer. Responses may be cached server-side.

7. External links

The site may link to external services (for example Wardog Servers). Following such a link leaves this website; the external provider’s privacy terms apply. External sites are not loaded invisibly in the background.

8. No analytics / advertising / profiling

The application includes no analytics/tracking scripts, no advertising, no social-media pixels and no third-party fonts. Frontend assets (CSS/JS/images/logos) are self-hosted.

9. Retention

  • optional localStorage preferences: until disabled/deleted by the user
  • rate-limit counters: volatile in memory, window-based
  • upstream caches: short-lived in Node process memory
  • local desktop use: no central hosting logs by this project
